==================================================
DEVOPS SPECIAL — USER TESTING MANUAL
==================================================

This document is a comprehensive, step-by-step practical testing manual for DevMate (DevOps Special). Use this manual to verify every feature, workflow, visual indicator, and edge case of the application directly in your web browser.

--------------------------------------------------
1. BEFORE YOU START
--------------------------------------------------

Requirements:
- Python 3.8+ installed
- Web browser (Chrome, Firefox, Edge, or Safari)
- Optional: Docker Desktop (running) for Docker Image Analysis
- Optional: Trivy CLI installed for Trivy CVE Scanning

How to Start the Application:
1. Open a terminal / PowerShell window in the project folder:
   d:\projects\miniProject_sem5_old\devops-special
2. Start the Flask server:
   python app.py
   (or: py app.py)
3. Confirm the terminal displays:
   🧠 DevMate Backend running on http://127.0.0.1:5000
4. Open your browser and navigate to:
   http://127.0.0.1:5000

Confirm Application Loaded Correctly:
- ACTION: Observe the topbar navigation bar.
- EXPECTED RESULT: You should see the DevMate logo ("🧠 DevMate"), three topbar tabs ("🔍 Analyzer", "🎓 Academy", "📦 Image"), and the "Beginner Mode" toggle switch (checked by default).

--------------------------------------------------
2. BASIC ANALYZER TEST
--------------------------------------------------

Test Dockerfile Analysis:
- ACTION: Click the "🔍 Analyzer" tab. In the "Dockerfile" input area, paste the following sample Dockerfile:

FROM python:latest
COPY . /app
WORKDIR /app
CMD ["python", "app.py"]

- ACTION: Click the "🔍 Analyze Deployment Readiness" button.
- EXPECTED RESULT: 
  - The results panel smoothly scrolls into view.
  - The readiness score ring displays a calculated score (e.g. 50/100) with status "Not Ready" or "Significant Gaps".
  - The Category Breakdown shows score penalties under "Security" and "Best Practices".
  - Finding cards appear:
    - [High] DF001: Base image 'python:latest' uses an unpinned tag.
    - [Critical] DF002: No USER directive found — container runs as root by default.
    - [Medium] DF003: No HEALTHCHECK instruction.
    - [Medium] DF004: COPY doesn't use --chown.
    - [Low] DF005: No EXPOSE instruction.

Test Kubernetes Analysis:
- ACTION: In the "Kubernetes Manifest" input area, paste the following sample manifest:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 1
  template:
    spec:
      containers:
      - name: web
        image: nginx:latest

- ACTION: Click "🔍 Analyze Deployment Readiness".
- EXPECTED RESULT:
  - Findings list updates to include Kubernetes findings:
    - [Critical/High] K8S001: Container has no resource limits/requests.
    - [High] K8S002: No readinessProbe defined.
    - [High] K8S003: No livenessProbe defined.
    - [Medium] K8S004: No securityContext defined.
    - [Medium] K8S005: Image uses ':latest' tag.
  - Score updates to reflect combined Dockerfile + K8s penalties.
  - Roadmap section appears listing recommended fixes in order of weight impact.

4. LESSON VIEW
--------------------------------------------------

- ACTION: From the Academy tab, click any lesson card (e.g. "DF002: Avoid Running Containers as Root").
- EXPECTED RESULT:
  - The lesson view slides open displaying the lesson title, category chip, severity tag, and difficulty tag.
  - Sections rendered:
    1. Plain Explanation (simple analogy)
    2. Technical Explanation (in-depth DevOps context)
    3. Why It Matters (risk & blast radius)

- EXPECTED RESULT: "📋 Copy Fix" and "📋 Copy Code" buttons appear on hover.
- ACTION: Click "Back to Academy".
- EXPECTED RESULT: Returns smoothly to the 12-lesson grid view.

Analyzer → Academy Bridge ("Take Lesson"):
- ACTION: Go to "🔍 Analyzer", paste `FROM python:latest`, and click "Analyze Deployment Readiness".
- ACTION: Expand finding DF001 card, scroll to the bottom of the card, and click "🎓 Take Academy Lesson (DF001)".
- EXPECTED RESULT: Immediately opens the DF001 lesson detail view in the Academy tab.

5. QUIZ + MASTERY
--------------------------------------------------

- ACTION: Open lesson "DF002" in Academy. Scroll to the "Knowledge Check" quiz.
- ACTION: Select an INCORRECT option and click "Submit Answer".
- EXPECTED RESULT:
  - Red error alert appears: "❌ Incorrect. Try again!"
  - Quiz options remain interactive for retry. No XP or mastery awarded.
- ACTION: Select the CORRECT option ("If compromised, attacker has full root access") and click "Submit Answer".
- EXPECTED RESULT:
  - Green success alert appears: "🎉 Correct! You've mastered this rule! (+10 XP)".
  - A visual celebration confetti particle burst fires across the screen.
  - Floating toast notification appears: "+10 XP Earned!".
  - XP counter in the header updates from 0 XP to 10 XP.
  - Mastered tracker updates to "1 / 12 Mastered".
  - The lesson card in the grid now shows a green "Mastered" badge.
- ACTION: Re-open lesson "DF002", select the correct answer again, and click "Submit Answer".
- EXPECTED RESULT: Answer is confirmed, but no additional XP or duplicate confetti is awarded.

Analyzer Inline Quiz Sync:
- ACTION: Go to "🔍 Analyzer", expand finding DF002 card.
- EXPECTED RESULT: The inline quiz inside the Analyzer card shows that the quiz is already passed / mastered.

--------------------------------------------------
12. CERTIFICATE VERIFICATION
--------------------------------------------------

Location: Bottom of Certificate panel in Academy tab (`#verifyCertPanel`).

Test Case 1: Empty Input
- ACTION: Leave verify input blank and click "Verify".
- EXPECTED RESULT: Warning box appears: "⚠️ Please enter a Certificate ID to verify." (`.verify-result.warning`).

Test Case 2: Valid Current-Session ID
- ACTION: Unlock certificate, copy the generated ID (e.g. `DM-CERT-A1B2-C3D4`), paste it into the input, and click "Verify" or press `Enter`.
- EXPECTED RESULT: Success box appears: "✅ Certificate Verified!" showing Recipient Name, Cert ID, Verification Code, Issue Date, and 12/12 Mastery Status (`.verify-result.success`).

Test Case 3: Invalid / Partial ID
- ACTION: Enter an invalid ID (e.g. `DM-CERT-INVALID-999` or partial `DM-CERT`) and click "Verify".
- EXPECTED RESULT: Error box appears: "❌ Verification Failed / Invalid ID" stating the ID does not match active session records (`.verify-result.error`).

Test Case 4: Retype Auto-Clear
- ACTION: With a verification result displayed, type a new character in the input box.
- EXPECTED RESULT: The result box immediately hides and clears, preventing stale verification feedback.

Test Case 5: Session Expiry (Post-Refresh)
- ACTION: Refresh the browser (`F5`). Enter any previously generated Certificate ID.
- EXPECTED RESULT: Warning box appears: "🔒 No Active Certificate in Session" explaining that session memory was reset on page reload.

14. DOCKER IMAGE ANALYSIS
--------------------------------------------------
[Requirement: Docker Desktop installed and daemon running]

- ACTION: Click the "📦 Image" tab in the topbar navigation.
- EXPECTED RESULT: Image inspection view displays input row, placeholder `e.g. nginx:1.27`, and "Analyze Image" button.

Test Case 1: Inspect Local Image
- ACTION: Enter a locally pulled image name (e.g. `nginx:1.27` or `python:3.12-slim`) and click "Analyze Image" or press `Enter`.
- EXPECTED RESULT:
  - Skeleton loader animates during fetch.
  - Results display Metadata Card: Image ID, Platform (Architecture/OS), Created Date, Size, Layer Count, User, Working Directory, Exposed Ports, Entrypoint, CMD, and expandable Environment Variables accordion.
  - Security Findings list displays image-level risk cards:
    - `IMG001` (High) if running as root
    - `IMG002` (Medium) if using `:latest` tag
    - `IMG003` (Low) if >3 exposed ports
    - `IMG004` (Low) if missing `WORKDIR`
    - `IMG005` (Low) if missing `ENTRYPOINT`/`CMD`

Test Case 2: Image Not Found Locally
- ACTION: Enter `nonexistent-image-xyz:99.99` and click "Analyze Image".
- EXPECTED RESULT: Error banner appears: "📦 Image not found locally: Image 'nonexistent-image-xyz:99.99' was not found locally. Pull it first: docker pull nonexistent-image-xyz:99.99".

Test Case 3: Docker Daemon Not Running / Unavailable
- ACTION: Stop Docker Desktop (or run command when Docker is stopped) and analyze any image.
- EXPECTED RESULT: Error banner appears: "🐳 Docker unavailable: Docker is not installed or the Docker daemon is not running." (Backend returns HTTP 503 without crashing).

18. ERROR / EDGE CASE TESTS
--------------------------------------------------

1. Empty Input (Analyzer):
- ACTION: Clear both textareas in "🔍 Analyzer" and click "Analyze Deployment Readiness".
- EXPECTED RESULT: Red warning toast/error message: "Please provide a Dockerfile or Kubernetes manifest to analyze."

2. Invalid YAML (Kubernetes):
- ACTION: Paste broken YAML (e.g. `kind: Deployment \n   bad_indentation`) and analyze.
- EXPECTED RESULT: Critical finding `K8S900`: "Invalid YAML syntax — the manifest cannot be parsed". Readiness score drops significantly.

3. Invalid Image Ref (Image Tab):
- ACTION: Enter invalid characters like `nginx; rm -rf /` in image input and click "Analyze Image".
- EXPECTED RESULT: Error message: "⚠️ Invalid image reference. Use format: name:tag". (Backend regex rejects invalid characters without subprocess invocation).

--------------------------------------------------
19. SESSION-ONLY BEHAVIOR
--------------------------------------------------

The following state is held strictly in volatile browser memory (`script.js` variables) and will reset upon page reload (`F5`):
- Academy lesson mastery (0 / 12)
- Total XP accumulated
- Unlocked badges
- Certificate unlock status & generated Certificate ID
- Active verification query state

The following behavior should NOT be expected to persist across restarts:
- Saving progress to a database (DevMate operates client-side / session-only without persistent DB until Phase 3).
